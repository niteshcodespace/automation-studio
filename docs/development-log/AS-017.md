# AS-017 - Environment Management

> Last updated: 2026-07-24

## Objective

Define and then deliver Project-scoped Environment management for base URLs, non-secret runtime
configuration, external secret references, lifecycle, and default selection while evolving the
existing Environment aggregate and preserving Execution history.

## AS-017D Implementation Evidence

- Added the `EnvironmentService` interface and `EnvironmentServiceImpl` with Project-scoped create,
  read, list/page, combined status/type/default filtering, current-default lookup, metadata update,
  lifecycle change, default change, and delete operations.
- Added service-layer `CreateEnvironmentCommand` and `UpdateEnvironmentCommand` records so the
  service remains independent of the future REST request DTO and `If-Match` parsing work.
- All operations verify Project existence, and Environment lookups remain scoped by Project so
  missing and cross-Project resources produce the same not-found outcome.
- Create and update normalize names and descriptions, validate bounded absolute HTTP(S) base URLs,
  require typed enums, default null JSON maps to empty objects, and enforce the 65,536-byte
  canonical serialized UTF-8 limit with the configured application `ObjectMapper`.
- Configuration validation recursively and case-insensitively rejects the documented exact
  secret-shaped keys while reporting only the safe key path. Secret references require top-level
  nonblank string values with an opaque URI-style scheme prefix. Neither validation path logs or
  exposes rejected values.
- Update, status, default, and delete operations require the caller's expected current version.
  Explicit mismatches and JPA optimistic-lock failures translate to the existing conflict outcome;
  the entity's `@Version` field remains persistence controlled.
- Every operation that can affect a default locks the owning Project first, then performs scoped
  Environment/default lookups, clears the previous default where needed, applies the target state,
  and flushes inside the transaction.
- Clearing a previous default is explicitly flushed before setting or inserting its replacement so
  PostgreSQL's partial unique index is never transiently violated by Hibernate statement ordering.
  That flush increments the previous default's JPA version, which is asserted by tests.
- Moving a default Environment to INACTIVE or ARCHIVED clears it. Reactivation never restores the
  default, clearing or deleting a default leaves the Project without one, and no replacement is
  selected automatically.
- Added the minimal Project/Environment-scoped Execution existence query for a clear delete
  pre-check. The restrictive database foreign key remains authoritative, and a concurrent
  foreign-key violation is translated to a safe referenced-delete conflict without exposing SQL
  or constraint details.
- Added 20 focused service unit tests covering scoped outcomes, normalization and validation,
  create/update/version behavior, lifecycle/default rules, filtering, and delete conflict
  translation.
- Added 6 PostgreSQL/Testcontainers service integration tests covering atomic default replacement,
  version and stale-version behavior, lifecycle clearing/reactivation, deletion protection,
  Project isolation, and two concurrent default requests serialized through the Project lock with
  exactly one final default.

## Important Decisions

- Evolve the existing aggregate; never create a duplicate Environment model/table.
- Preserve existing identifiers, ownership, names, base URLs, timestamps, uniqueness, and
  restrictive Execution relationships.
- Add description, type, two non-null JSONB objects, default flag, optimistic version, ARCHIVED,
  an ACTIVE-default check constraint, and a partial Project-default unique index in AS-017B.
- Require an absolute HTTP(S) base URL with a host and no user-info or fragment.
- Limit each serialized JSON object to 64 KiB.
- Contractually restrict configuration to non-secret runtime data and recursively reject the
  documented case-insensitive secret-shaped keys as defence in depth, without claiming arbitrary
  JSON can be proven secret-free.
- Accept only nonblank URI-style strings in secretReferences; credential resolution remains
  runner-only, and rejected values/JSON payloads never enter logs or errors.
- Serialize default changes through a Project lock and retain a partial unique index as the final
  invariant safeguard.
- Clear the default when it leaves ACTIVE and never auto-promote a replacement.
- Require `If-Match` expected versions for PUT, both PATCH operations, and DELETE; reject missing
  or malformed headers with 400 and version/JPA conflicts with 409 while JPA owns persisted versions.
- Translate duplicate names, protected deletion, default constraints, and optimistic conflicts to 409.

## Assumptions and Open Gate

No existing convention defines a JSON payload byte limit, so AS-017A establishes and retains
64 KiB per JSON object as the accepted bounded-input rule.

Legacy rows have no authoritative persisted Environment classification. AS-017B therefore
backfills them to TEST explicitly to preserve upgrade compatibility. This is not a claim about
their actual targets; users may correct classifications through the API after delivery.
