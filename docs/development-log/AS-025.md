### Architecture findings

The existing implementation already provides immutable execution contexts, deterministic
non-secret variable precedence, immutable secret references, scheduling/claim/lease ownership,
secure workspace and source preparation, provider-neutral engine/result boundaries, a declarative
Playwright engine, same-origin enforcement, sanitized failures, and deterministic browser cleanup.

Resolved secrets are intentionally absent. They must not be added to `ExecutionContext` or its
variables. ADR-015 therefore defines a separate execution-scoped capability, an exact
provider-reference resolver, and schema `"2.0"` `fill.secretRef`. Schema `"1.0"` and
`NonSecretVariableInterpolator` retain their existing non-secret semantics.

OrangeHRM remains scenario/environment data. The platform gains no OrangeHRM-specific queue,
orchestrator, engine, result, persistence model, endpoint, or Java branch.

## 2026-08-02 - AS-025B Secret Resolution Boundary

### Scope implemented

- added a provider-neutral `ExecutionSecretProvider` port and immutable duplicate-safe provider
  registry;
- added one execution-bound `ExecutionSecretScope` with case-sensitive explicit-name access,
  bounded defensive reference copies, lazy resolution, cross-execution isolation, and idempotent
  cleanup;
- added a non-record `ResolvedSecret` container with redacted representation, defensive character
  copies, bounded values, consumer-copy clearing, post-close rejection, and mutable backing-store
  clearing;
- added fixed-code, fixed-message `SecretResolutionException` handling and reconstructed untrusted
  provider failures without retaining raw causes;
- added the exact ADR-015 `{provider, key}` `operator-environment` adapter, requiring bounded
  `AUTOMATION_SECRET_` keys, an exact provider identifier, an exact two-field object, and no
  fallback;
- made the production adapter absent by default and available only when
  `automation.runner.secrets.operator-environment.enabled=true`; and
- added a scope factory for future AS-025D orchestration composition without wiring it into any
  engine or orchestrator in AS-025B.

### Security behavior

- resolution occurs only for an explicitly requested admitted logical name;
- duplicate names, unknown names, invalid references, unavailable/ambiguous/disabled providers,
  missing values, blank values, oversized names/keys/values, closed values/scopes, null inputs, and
  unexpected provider failures fail closed;
- no resolved-secret map or collection view is exposed;
- public messages, exception representations, scope/value representations, and provider failures
  contain no logical name, provider key, raw reference, resolved value, or provider diagnostic;
- future provider exceptions are treated as untrusted and mapped to allowlisted fixed
  classifications; and
- deterministic canaries exist only in unit tests and leakage assertions.
