## 2026-08-02 - AS-025B Secret Resolution Boundary

### Scope implemented

- added a provider-neutral `ExecutionSecretProvider` port and immutable duplicate-safe provider
  registry;
- added one execution-bound `ExecutionSecretScope` with case-sensitive explicit-name access,
  bounded defensive reference copies, lazy resolution, cross-execution isolation, and idempotent
  cleanup;
- added a non-record `ResolvedSecret` container with redacted representation, defensive character
  copies, bounded values, consumer-copy clearing, post-close rejection, and mutable backing-store
  clearing;
- added fixed-code, fixed-message `SecretResolutionException` handling and reconstructed untrusted
  provider failures without retaining raw causes;
- added the exact ADR-015 `{provider, key}` `operator-environment` adapter, requiring bounded
  `AUTOMATION_SECRET_` keys, an exact provider identifier, an exact two-field object, and no
  fallback;
- made the production adapter absent by default and available only when
  `automation.runner.secrets.operator-environment.enabled=true`; and
- added a scope factory for future AS-025D orchestration composition without wiring it into any
  engine or orchestrator in AS-025B.

### Security behavior

- resolution occurs only for an explicitly requested admitted logical name;
- duplicate names, unknown names, invalid references, unavailable/ambiguous/disabled providers,
  missing values, blank values, oversized names/keys/values, closed values/scopes, null inputs, and
  unexpected provider failures fail closed;
- no resolved-secret map or collection view is exposed;
- public messages, exception representations, scope/value representations, and provider failures
  contain no logical name, provider key, raw reference, resolved value, or provider diagnostic;
- future provider exceptions are treated as untrusted and mapped to allowlisted fixed
  classifications; and
- deterministic canaries exist only in unit tests and leakage assertions.

## 2026-08-03 - AS-025C Manifest and Sensitive Fill Composition

### Scope implemented

- preserved schema `"1.0"` field admission and ordinary `fill.value` semantics;
- added explicit schema `"2.0"` support with `fill.secretRef` as the only new field;
- required schema `"2.0"` fills to contain exactly one of `value` or `secretRef`;
- bounded logical names to 128 characters with the AS-025B case-sensitive name grammar and
  rejected blank, malformed, non-string, oversized, object-shaped, mixed, non-fill, and unknown
  fields;
- retained strict duplicate-key detection and rejected future schema versions;
- added a narrow sensitive-fill resolver to the Playwright action context while preserving its
  existing constructor with a fixed fail-closed unavailable capability;
- resolved only explicit logical names through AS-025B `ExecutionSecretScope` composition in
  focused tests;
- converted the owned character value to the unavoidable transient runtime string only at the
  final fill call and closed the handle immediately through try-with-resources; and
- retained the existing `NonSecretVariableInterpolator` unchanged for ordinary values.

### Security and compatibility behavior

- selectors and timeouts validate before secret resolution;
- secret values never enter ordinary variable maps, manifest objects, context, outcomes, metrics,
  or fixed action failures;
- unresolved names, unavailable or closed capabilities, invalid handles, and resolution failures
  map to fixed `SENSITIVE_FILL_RESOLUTION_FAILED` errors without causes;
- runtime failures on the sensitive path map to fixed cause-free action errors and still close the
  handle;
- multiple fills select their exact logical names and independent execution scopes remain
  isolated; and
- existing schema `"1.0"`, action ordering, metrics, assertion, and non-secret interpolation
  behavior remains covered by regression tests.

### Independent AS-025C review

The independent review confirmed the schema, action, secret-lifetime, and phase boundaries and
found two issues before final verification:

- generic runtime failures from a future sensitive resolver could escape without the fixed
  sensitive-fill classification; resolution now reconstructs all non-platform runtime failures as

- ordinary fill timeout validation had moved before non-secret interpolation, changing a schema
  `"1.0"` failure-order edge case; the original selector, interpolation, then timeout order is
  restored, while sensitive fills still validate timeout before resolution.

The review also prompted an explicit domain invariant preventing direct construction of a schema
`"1.0"` manifest containing a secret reference. Post-correction focused/regression, compilation,
full-suite, and diff checks passed. No review finding remains.
