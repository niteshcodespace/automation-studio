### Architecture findings

The existing implementation already provides immutable execution contexts, deterministic
non-secret variable precedence, immutable secret references, scheduling/claim/lease ownership,
secure workspace and source preparation, provider-neutral engine/result boundaries, a declarative
Playwright engine, same-origin enforcement, sanitized failures, and deterministic browser cleanup.

Resolved secrets are intentionally absent. They must not be added to `ExecutionContext` or its
variables. ADR-015 therefore defines a separate execution-scoped capability, an exact
provider-reference resolver, and schema `"2.0"` `fill.secretRef`. Schema `"1.0"` and
`NonSecretVariableInterpolator` retain their existing non-secret semantics.

OrangeHRM remains scenario/environment data. The platform gains no OrangeHRM-specific queue,
orchestrator, engine, result, persistence model, endpoint, or Java branch.

### Independent requirements review
