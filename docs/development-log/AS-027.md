`studio-api` combines the engine contract with Spring Boot/Web/Data, Hibernate, Flyway,
PostgreSQL, Playwright, Testcontainers, JUnit, and other platform concerns. The `engines/`

The complete dependency inspection covered `ExecutionEngine`, descriptor, request, result/state,

conformance interface.

## Dependency findings

- `ExecutionEngine` imports platform `ExecutionContext` and legacy lifecycle `ExecutionResult`.
- `ExecutionContext` includes runner, retry, metadata, secret-reference, suite, environment, and
  variable graphs beyond the minimum demonstrated reusable surface.
- `EngineExecutionRequest` imports platform preparation, workspace-state, source-materialization,
  and secret types.
- legacy `ExecutionResult` reaches evidence types that must not pre-empt AS-028.
- platform workspace access exposes `Path` and its request imports Jackson and preparation types.
- the current conformance interface depends on JUnit, AssertJ, and
  `ExecutionEngineRegistryImpl`.
- Builtin and Playwright canonical execution require exact request/result identity; Playwright
  additionally consumes suite configuration/reference, environment base URL, non-secret variables,
  logical secret access, and bounded prepared-source access.

Publishing `studio-api` or moving the existing closure unchanged was rejected.

## Architecture checkpoint

The approved direction separates a JDK-only production SDK from JUnit-based conformance support,
projects a least-authority engine context, retains one platform registry and orchestration path,
keeps a platform compatibility bridge, and exposes only execution-bound workspace/secret
capabilities. Exact DTO/package/workspace operations remain AS-027B validation decisions.

Plugins remain trusted statically deployed in-process code. The SDK is not a sandbox. Runtime
discovery/installation/isolation and durable artifact design remain deferred.

## AS-027B minimal engine plugin SDK implementation

Created a root Maven reactor with `engines/engine-plugin-sdk` and `backend/studio-api`. The Java 21
SDK has no declared dependencies and owns `ExecutionEnginePlugin`, `ExecutionEngineDescriptor`,
`EngineIdentity`, `EngineExecutionContext`, `EngineExecutionRequest`, `EngineExecutionResult`,
`EngineExecutionState`, `WorkspaceId`, `PreparedSource`, `PreparedSourceAccess`, `WorkspaceAccess`,
`ExecutionSecretAccess`, `ResolvedSecret`, and `SecretResolutionException`.

The context projection exposes execution ID, exact engine identity/version, suite reference and
configuration, environment base URL and configuration, and string-valued non-secret variables.
Nested maps/lists are defensively frozen. Runner claims, fencing, persistence, scheduling, retry
ownership, secret-provider metadata, physical roots, and lifecycle state remain excluded.

Prepared source access is execution/workspace-bound and provides relative file streams only. The
platform adapter rejects absolute/traversing paths, symlinks, non-regular files, escaped real paths,
and use after close. Secret access remains logical-name-only and execution-correlated; resolved
character data is copied, consumer copies are cleared, close is deterministic, and rendering is
redacted.

`ExecutionEngine` extends the SDK plugin interface. Builtin and Playwright implement the canonical
SDK methods with identities `BUILTIN / 1.0.0` and `playwright-java / 1.61.0`. Deprecated platform
validation, prepared-request, and lifecycle invocation remain compatible. The orchestrator uses the
SDK request for migrated plugins and a narrowly detected deprecated prepared-request override for
legacy implementations. The existing `ExecutionEngineRegistryImpl` remains the only registry.

## AS-027E sample engine plugin

Added `engines/sample-engine-plugin` to the root reactor as a non-production reference module.
Its production dependency is only `engine-plugin-sdk`; `engine-plugin-conformance` and JUnit 5 are
test-scoped. The module has no dependency on `studio-api`, Spring, persistence, Jackson,
Playwright, Testcontainers, or provider infrastructure, and it is not registered or advertised as
an Automation Studio production engine.

`SampleExecutionEnginePlugin` has exact case-sensitive identity `sample-engine / 1.0.0`, an
immutable minimal descriptor, and only the canonical SDK methods `descriptor()`,
`validate(EngineExecutionContext)`, and `execute(EngineExecutionRequest)`. Validation accepts the
single immutable configuration `{mode=DETERMINISTIC}` and performs no resource acquisition. The
plugin has no platform compatibility overload.

Canonical execution validates request correlation, reads repository-relative `sample.txt` through
`WorkspaceAccess` and `PreparedSourceAccess`, resolves logical `sample-token`, uses the value only
inside the bounded in-memory callback, and deterministically closes the stream, prepared-source
handle, and resolved value. A caller-provided JDK `Clock` makes timing deterministic. The returned
SDK result correlates execution, exact engine identity/version, workspace, revision, success
state, timestamps, and duration. Invalid configuration and execution expose fixed sanitized
messages without configuration, source, path, or secret values.

`SampleExecutionEngineConformanceTest` inherits the reusable AS-027C contract and supplies three
isolated requests with observable workspace and secret cleanup. It proves descriptor validity,
exact request targeting, side-effect-free validation, result/timing correlation, provider-neutral
signatures, cleanup, and concurrent invocation isolation. Three sample-specific tests cover exact
identity, sanitized invalid configuration, and sanitized invalid prepared input without
duplicating generic assertions.
