# AS-028 - Execution Artifact and Evidence Contract Development Log

## Feature objective

Standardize durable cross-engine artifact publication, metadata, integrity, discovery, and
evidence semantics without granting engines storage, database, lifecycle, workspace-lifecycle, or
retention authority.

## Discovery findings

- The roadmap assigns AS-028 artifact categories, metadata, publication, integrity, retention
  references, redaction, limits, and provider-neutral discovery.
- AS-022 described an orchestrator-owned evidence sink but deferred storage implementation.
- Platform evidence values and validation exist, but legacy evidence is disconnected from the
  current controlled pipeline.
- `execution_artifact` and a JPA entity/repository exist, but no production service persists
  engine evidence through that repository.
- Runtime and database category vocabularies conflict.
- Workspaces contain an `artifacts/` directory, but normal release deletes the whole workspace.
- No durable artifact storage port or local adapter exists despite aspirational architecture text.
- SDK result/workspace types intentionally expose no artifact or write authority.
- Builtin produces only a logical zero-byte compatibility reference; Playwright produces no
  durable screenshots, traces, videos, logs, or reports in production.

## AS-028A decisions

Artifact means one immutable durable item: externally stored bytes plus persisted metadata.
Evidence is the execution-scoped collection of artifact records and bounded summary facts.

The approved hybrid model supplies a narrow execution-scoped publisher, uses platform-controlled
streaming/staging, validates bounded declarations, computes actual size and SHA-256, finalizes to a
durable local store outside workspace cleanup, and persists immutable PostgreSQL metadata.

Engines produce content and propose bounded descriptive fields. Platform infrastructure owns IDs,
opaque keys, validation, integrity, publication, persistence, association, abort, and retention-
reference selection. Workspace and lifecycle ownership remain unchanged. Retention execution stays
with AS-080 and S3-compatible storage stays with AS-078.

AS-028A authorized no SDK, Java, test, POM, configuration, migration, storage, persistence, or
engine implementation.

## AS-028B implementation

AS-028B adds the JDK-only `ArtifactCategory`, `ArtifactPublication`, `ArtifactPublisher`,
`ArtifactReceipt`, and `ArtifactPublicationException` contracts. Categories have exact extensible
value semantics and common constants. A publication carries only validated category, logical name,
media type, immutable bounded metadata, and a streaming writer callback. The publisher owns the
callback output stream. Receipts contain safe platform-result fields without storage references,
paths, URIs, credentials, persistence types, or provider types. Publication failures expose only a
stable code and safe message without a raw provider cause.

`EngineExecutionRequest` now carries an execution-correlated publisher. Its existing four-argument
constructor remains available and binds an unavailable publisher: zero-artifact callers continue
unchanged, while accidental publication fails explicitly rather than simulating success.
`ExecutionEnginePlugin`, `EngineExecutionResult`, `WorkspaceAccess`, and `PreparedSourceAccess`
remain unchanged.

The reusable conformance module adds `InMemoryArtifactPublisher`, an explicitly non-durable SDK-only
fixture. Tests cover category/declaration validation, metadata and receipt immutability, execution
correlation, SHA-256 observation, safe diagnostics, bounded in-memory content, stream closure,
zero-artifact compatibility, and concurrent execution isolation. Builtin, Playwright, and sample
engines remain zero-artifact compatible; no engine capture was added.

SDK declaration limits selected in AS-028B are: category 128 characters, logical name 255, media
type 255, 32 metadata entries, metadata key 128, metadata value 1,024, and total UTF-8 metadata
8,192 bytes. Production byte, cumulative, count, duration, and concurrent-open-publication limits
remain AS-028C decisions; the fixture's one-MiB bound is test-only.

Dependency verification confirms `engine-plugin-sdk` has no dependencies;
`engine-plugin-conformance` has only the SDK and JUnit 5; sample production has only the SDK; and
`studio-api` consumes the SDK as its reusable production contract. No Spring, persistence,
Playwright, Testcontainers, Jackson, path, storage-provider, or platform type enters the SDK.

Focused verification covered 48 tests with zero failures, errors, or skips. Full reactor
`mvn clean verify` covered all four modules with 1,164 tests, zero failures, zero errors, 16 skipped,
and `BUILD SUCCESS`. Verification remained external-target, operator-secret, real-browser,
durable-publication, and runtime-plugin-loading inert.

Independent review found no blocking issue in dependency purity, provider neutrality, execution
correlation, immutability, path/provider leakage, stream ownership, diagnostics, compatibility,
concurrency isolation, or platform ownership. No AS-028C storage, persistence, migration,
orchestration, retention, or engine-capture work is present.

AS-028B is committed and pushed at `43c4226`.

## AS-028C implementation

AS-028C adds a platform-internal `ArtifactStorage` port, immutable opaque storage key/reference and
outcome values, a local-filesystem adapter, validated configuration, and an execution-scoped
`StorageBackedArtifactPublisher`. None of these types enters the reusable SDK. Production
orchestration continues to supply the unavailable compatibility publisher until AS-028E.

The local adapter streams to a publisher-owned pending file beneath a configured durable root,
computes actual bytes and SHA-256 while writing, closes successfully, and finalizes with an atomic
move when supported or a same-filesystem non-replacing move fallback. UUID-derived platform keys,
not logical names or media types, determine filenames. References use opaque `artifact:v1:<UUID>`
values and expose no path. Relative roots, filesystem roots, overlapping workspace roots, symlink
segments, changed roots, invalid references, and target collisions fail closed. Failed pending
content is removed best effort; AS-080 retains operational orphan handling.

Selected defaults under `automation.runner.artifacts` are 100 MiB per artifact, 1 GiB cumulative
per execution, 100 finalized artifacts per execution, and four concurrent open publications per
execution. Configuration rejects non-positive or inconsistent values at startup. The publisher
keeps bounded in-memory counters per execution instance; failures do not consume finalized quota,
concurrent quota races are resolved under a lock, and a losing finalized write is deleted. Durable
restart accounting remains deferred to AS-028D/E rather than being represented as persistent.

The internal outcome contains only opaque reference, actual size, `SHA-256`, digest, and finalized
timestamp. Internal verification streams stored bytes and compares exact size/digest. The SDK
receipt is created from the verified storage outcome but still exposes no storage reference.

Focused verification covered 21 tests with zero failures, zero errors, and one skipped Windows
symbolic-link creation case. Full reactor `mvn clean verify` covered all four modules with 1,178
tests, zero failures, zero errors, 17 skipped, and `BUILD SUCCESS`. Tests prove exact/over-limit
boundaries, cumulative/count/concurrency quotas, failed accounting, execution isolation, known
SHA-256, corruption detection, collision behavior, partial cleanup, sanitized diagnostics, opaque
placement, and durable survival after independent workspace deletion.

Independent security and architecture review found no blocking issue in traversal/symlink/root
resistance, opaque keys, streaming, quotas, concurrency, cleanup, integrity, diagnostics, provider
neutrality, SDK purity, workspace separation, or ownership. No database metadata persistence,
Flyway migration, discovery API, orchestration wiring, Playwright capture, S3, download, lifecycle,
or retention implementation is present.

## Reconciled contradictions

Current-state documentation is corrected to distinguish the planned local artifact adapter from
implemented code. The requirements and ADR record that runtime/database categories require
reconciliation, legacy evidence is not on the controlled pipeline, and the entity/repository do
not imply active persistence. Historical AS-007 cascade reporting remains contemporaneous; the
authoritative current schema uses V6 `ON DELETE RESTRICT`. AS-027 roadmap current status is updated
without rewriting its delivery history.
