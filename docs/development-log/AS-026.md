## Terminology and version decisions

Canonical identity terms are `engineId` and `implementationVersion`. Both are opaque,
case-sensitive, exact strings. Display name, alias, bean name, registration order, version range,
case folding, trimming, fallback, and implicit defaults are never resolution inputs.

A separate plugin-contract version is deferred. Current compatibility uses the shared Java
contract plus exact implementation version. This reconciles historical conceptual contract-version
language without adding a field or negotiation policy unsupported by code.

## Compatibility decisions

Prepared `EngineExecutionRequest` is the canonical invocation direction. The legacy
`execute(ExecutionContext)` method remains temporarily for Builtin/default-adapter source
compatibility and is not a second orchestration path. Deprecated descriptor/constant aliases also
remain temporary read-only compatibility surfaces. No removal deadline is approved in AS-026A.

Repository-internal contract verification belongs to AS-026. A reusable SDK, external fixtures,
third-party harness, sample plugin, packaging, and developer distribution belong to AS-027.

## Workspace, source and secret boundaries

AS-023 continues to own physical workspace creation/release/deletion and exact source
materialization. Engines receive immutable preparation and narrow workspace access only, close
their access handles, and cannot choose/delete the physical workspace or alter source identity.

AS-025 continues to own execution-scoped secret provider selection, lazy resolution, admitted-name
binding, value lifetime, and scope cleanup. Resolved values remain outside descriptors, registry,
context, normal variables, persistence, results, logs, and errors. AS-026 introduces no provider or
secret authority.

## Result, cleanup and artifact decisions

The current `EngineExecutionResult` is provider-neutral and bounded to identity, prepared source/
workspace, normalized state, and timing. AS-026 may verify consistency and safe failure/cleanup
behavior but does not standardize durable artifacts.

Engines close invocation resources in reverse order. Orchestration retains invocation order,
secret-scope cleanup, and physical workspace release. Lifecycle services retain fenced durable
completion. ADR-014/ADR-015 failure precedence remains authoritative.

Durable artifact metadata, categories, publication, integrity, retention, and discovery remain
AS-028. Temporary engine/workspace files are not durable artifact references.

## AS-026C - Registry Resolution and Compatibility Hardening

### Repository baseline

### Implementation

AS-026C preserves the existing registry interface and static Spring registration model. It:

- validates and canonically sorts all engine supports before publishing registry state;
- retains immutable insertion-ordered maps and the immutable deterministic descriptor list;
- checks that each engine returns a stable descriptor during registration and lookup;
- maps null, throwing, or inconsistent descriptors to a fixed safe invalid-descriptor failure;
- distinguishes unsupported implementation version and ambiguous name-only resolution with narrow
  exception subclasses that preserve the existing compatibility-exception hierarchy; and
- keeps duplicate and unknown-engine failures separate without exposing requested identities,
  implementation classes, bean names, configuration, paths, or secrets.

secret, cleanup, scheduling, persistence, Flyway, REST, browser, or manifest behavior changed.

## AS-026D - Canonical Plugin Invocation Contract

### Repository baseline

Implementation began from clean synchronized local `main` at
`d8d05e7cd5cd304185b8311b2fe30f68274595ca`, containing the committed and reviewed AS-026C
registry hardening.

### Invocation callers discovered

The controlled production path in `ExecutionOrchestratorImpl` resolves one engine and invokes
`execute(EngineExecutionRequest)` once. Playwright and repository qualification engines already
override that prepared form directly.

The context-only `execute(ExecutionContext)` form is used by `BuiltinExecutionEngine`, the legacy
`ExecutionEngineInvoker`, its compatibility lifecycle fallback, and their tests. This is retained
as a deprecated source-compatible surface under ADR-016. It is not used by the controlled
orchestrator and no new caller was added.

### Canonical invocation and compatibility treatment

`ExecutionEngine.execute(EngineExecutionRequest)` is now explicitly documented as canonical and
no longer defaults through `execute(ExecutionContext)`. Both default methods fail closed when an
engine does not implement the selected direction. The legacy context method remains deprecated
without a removal date.

`BuiltinExecutionEngine` now implements prepared invocation directly and maps its existing
deterministic result into the provider-neutral result using exact request workspace/source
identity. Its deprecated context method delegates to the same private Builtin behavior for source
compatibility. `PlaywrightExecutionEngine` continues its existing prepared invocation and now uses
the shared exact descriptor validation before acquiring resources.

### Request invariants and least authority

`EngineExecutionRequest` still contains exactly three record components: immutable
`ExecutionContext`, verified `SourcePreparationResult`, and execution-scoped
`ExecutionSecretAccess`. Construction now fails closed for inconsistent preparation state,
execution identity, workspace state/identity, materialized-source workspace identity, source type,
or exact resolved revision. `validateFor` requires exact case-sensitive descriptor engine ID and
implementation version. Canonical `engineId` and `implementationVersion` accessors were added;
legacy naming accessors remain deprecated read-only aliases.

The request exposes no lease/claim token, repository, transaction, scheduler, completion service,
mutable entity, arbitrary provider registry, workspace root, sibling workspace, or durable-status
authority.

## AS-026E - Result, Failure and Cleanup Contract

### Repository baseline and documents

Implementation began from clean synchronized local `main` at
`03790ec52660771f78668e522fdfe01e0772eabe`, containing the committed and reviewed AS-026D
canonical invocation contract. Discovery reconciled the AS-026 requirements, ADR-016,
implementation plan, development log, master roadmap, module architecture, and relevant AS-022
through AS-025 result, failure, secret, workspace, lifecycle, and cleanup decisions.

### Result producers and consumers

Production result producers are `BuiltinExecutionEngine` and `PlaywrightExecutionEngine`.
Repository integration and qualification fakes also construct the same provider-neutral record.

`ExecutionOrchestratorImpl` is the authoritative result validator and cleanup coordinator.
`ExecutionOrchestrationResult` carries the validated result to `RunnerPipelineCoordinatorImpl`,
which maps only normalized engine state to the existing fenced durable terminal statuses. Engines
do not receive or assign database status.

### Canonical result decision

`EngineExecutionResult` remains an immutable record containing only execution ID, canonical
`engineId`, canonical `implementationVersion`, workspace ID, resolved source revision, normalized
engine state, timestamps, and duration. Legacy `engineName()` and `engineVersion()` remain
deprecated read-only source-compatibility aliases.

Construction rejects null/blank mandatory identity, null state/timing, finish-before-start,
negative duration, and duration/timestamp disagreement. `validateFor` performs exact correlation
against the canonical request and selected descriptor for execution, engine, implementation
version, workspace, and source revision. A bounded `toString` includes only execution/engine/
workspace/state identity and omits source revision, timestamps, duration, provider diagnostics,
paths, and secrets.

The normalized engine states remain `SUCCEEDED`, `FAILED`, and `CANCELLED`. They are engine-level
outcomes only. The pipeline maps success/failure to existing durable statuses; cancellation remains
owned by the existing cancellation lifecycle and cannot be converted into a new durable state by
an engine.

### Failure contract findings

The existing boundary already distinguishes source preparation, engine lookup/invariant,
engine execution, secret-scope creation/cleanup, and physical workspace cleanup using fixed
platform codes and messages. Provider exceptions are retained only as internal causes beneath the
sanitized `ENGINE_EXECUTION_FAILED` boundary. Playwright translates configuration, workspace
access, manifest, runtime, action, and cleanup failures into fixed engine-owned exceptions before
they cross orchestration. Invalid/null/mismatched results fail closed as
`ENGINE_RESULT_INVARIANT_VIOLATION`.

No new exception hierarchy was required. Raw provider, secret, path, URL, source, and target
messages remain excluded from the public boundary.

### Cleanup ownership, order, and precedence

The verified production order is:

```text
engine execution
    -> engine runtime/session cleanup
    -> engine workspace-access handle closure
    -> orchestration result validation
    -> execution secret-scope cleanup
    -> physical workspace release
    -> return to pipeline coordinator
    -> fenced terminal persistence
```

Playwright owns runtime/session and access-handle closure. `ExecutionSecretScope` owns resolved
secret handles and values. `ExecutionOrchestratorImpl` owns sequencing and failure composition.
`WorkspaceManager` owns physical release/deletion. `RunnerExecutionService` owns fenced terminal
persistence.

Engine cleanup failure prevents a result. Secret cleanup failure prevents success and suppresses
an earlier execution/result failure. Physical workspace release is attempted after secret cleanup;
workspace cleanup failure has final precedence and retains the prior sanitized failure as
suppressed context. Result-validation and engine exceptions both trigger scope and workspace
cleanup. Fenced completion occurs only after orchestration returns a validated, fully cleaned
outcome or the pipeline maps a sanitized orchestration failure to `ERROR`.
