## Architecture Review Reconciliation

The initial proposal was approved with five required refinements:

1. Action dispatch is explicitly pluggable through one executor per action and an immutable,
   duplicate-safe registry. A monolithic switch/case dispatcher is prohibited.
2. Immutable execution metrics begin with the first engine implementation and cover action totals,
   action outcomes, execution duration, and browser startup duration. Persistence and reporting
   remain out of scope. Metrics use an internal runtime-result carrier and do not modify the
   provider-neutral engine result in AS-024.
3. Every raw manifest selector passes through one internal `SelectorResolver`; no page-object
   framework is introduced.
4. Manifest schema identity is an explicit contract such as `"1.0"` with deterministic future
   version negotiation and backward-compatibility rules.
5. The initial one-Browser/one-Context/one-Page runtime remains extensible for future multiple
   pages, contexts, and bounded parallel execution without implementing those capabilities now.

The following approved decisions remain unchanged:

- declarative scenario manifest;
- immutable execution snapshots;
- Chromium and headless operation only;
- one BrowserContext and one Page initially;
- no Maven, Gradle, npm, or arbitrary Java execution;
- secure repository-relative loading;
- Playwright runtime abstraction;
- deterministic cleanup; and
- the AS-024A through AS-024H story sequence.

## AS-024B Implementation

AS-024B pins Playwright Java `1.61.0` and defines the stable `playwright-java` engine descriptor
at the same exact version without registering or implementing an execution engine. AS-022 has no
separate runtime-version dimension: the immutable snapshot, runner capability, descriptor, and

The strict parser consumes the existing immutable suite snapshot and accepts only Chromium,
headless operation, bounded millisecond action/navigation timeouts, bounded viewport dimensions,

will be carried by the future internal runtime result. AS-024B introduces no metrics or runtime

## AS-024D Implementation

AS-024D introduces the internal `PlaywrightRuntime` boundary, one production Chromium SDK
adapter, an immutable runtime session/result, and immutable execution-scoped metrics. Raw
Playwright, BrowserType, Browser, BrowserContext, and Page objects remain confined to the
package-private SDK adapter and handles. The runtime creates one blank page only and exposes no
raw SDK object through its public contracts.

Suite-owned headless, viewport, and locale values come exclusively from
`PlaywrightExecutionConfiguration`. Operator-owned browser startup timeout and optional executable
path come exclusively from `PlaywrightRuntimeProperties`; suite and manifest contracts cannot
override them. A valid configured executable is the effective launch target and does not require
Playwright's default Chromium executable; the default is validated only when no operator path is
configured. Paths remain absent from logs and public errors. The runtime properties are registered
through a scoped Spring configuration.

Startup creates Playwright, validates Chromium availability, launches Chromium, creates one
non-persistent context, and creates one blank page. Closure is idempotent and proceeds in reverse
order through page, context, browser, and Playwright. Partial startup failures close every resource
already created. A primary startup failure remains primary, while sanitized cleanup failures are
retained as suppressed failures; one cleanup failure does not prevent later cleanup. Session close
is coordinated so exactly one caller performs cleanup, concurrent callers wait for completion, and
all callers observe the same terminal cleanup failure. Successful-close logging occurs only after
failure-free cleanup; failed cleanup logs only its sanitized failure code.

The immutable `PlaywrightRuntimeMetrics` contract contains total, successful, and failed action
counts, total execution duration, and browser startup duration with non-negative consistency
validation. AS-024D initializes action counts and total execution duration to zero because action
execution remains deferred. Browser startup duration uses an injected monotonic ticker and spans
from immediately before Playwright creation through successful Chromium launch; context and blank
page creation are deliberately excluded. Zero duration and normal `System.nanoTime()` wrap-compatible
subtraction are supported; a negative computed delta fails closed with a sanitized typed timing
error. Failed startup produces no runtime result.

Runtime failures use stable sanitized codes for invalid configuration/properties, unavailable
configured/default Chromium executables, Playwright creation, launch, context/page creation, and
resource cleanup. Lifecycle logs contain only fixed event text or a sanitized failure code and
never include paths, launch diagnostics, manifest content, selectors, page content, or secrets.

## AS-024E Implementation

AS-024D is completed, approved, and committed. AS-024E adds six independent executors for the
approved navigate, click, fill, assert-visible, assert-text, and assert-url manifest actions. An
immutable duplicate-safe registry performs exact action lookup without a central switch or
`instanceof` dispatcher. Executors depend only on a narrow `PlaywrightActionRuntime` facade;
Playwright SDK types remain confined to the package-private Chromium adapter.

Every selector-bearing executor uses one CSS-only `SelectorResolver`. It preserves accepted CSS
without semantic rewriting and rejects blank, oversized, control-character, malformed, and
unsupported-strategy selectors with sanitized failures. A bounded interpolator expands only an
explicit immutable map of non-secret variables in approved URL, fill-value, and assertion fields;
it performs no environment, system-property, secret-provider, filesystem, or network lookup.

Navigation resolves relative targets against a validated HTTP/HTTPS base URL and compares scheme,
host, and effective port rather than string prefixes. Absolute targets and post-navigation URLs
must remain within the normalized origin; unsupported schemes, credentials, scheme-relative URLs,
malformed input, cross-origin targets, and escaping redirects fail closed without URL disclosure.

Assertion mismatches are immutable sanitized outcomes, not infrastructure exceptions. The ordered
runner preserves manifest order, dispatches one step at a time, and stops after the first assertion
or infrastructure failure. Its execution-scoped accumulator carries AS-024D browser-startup time,
records planned/successful/failed action invariants, and measures total action duration using a
monotonic ticker. AS-024E does not load manifests, create runtime resources, integrate an
`ExecutionEngine`, or map provider-neutral results; those composition responsibilities remain
deferred to AS-024F.
