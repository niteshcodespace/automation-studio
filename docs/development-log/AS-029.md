## AS-029B - Plugin Module and Configuration Contract

AS-029B adds `engines/rest-assured-engine-plugin` to the reactor with production dependencies only
on the unchanged SDK, provider-local REST Assured 6.0.1, and provider-local Jackson 3.1.4. Generic
conformance and JUnit are test-scoped. The SDK remains dependency-free, and neither reusable module
depends on the provider.

The plugin exposes exact identity `rest-assured` / `6.0.1`. Its strict version-one JSON manifest
models defaults, scenarios, requests, approved HTTP methods, parameters, headers, bounded optional
bodies, logical authentication references, structural assertions, retry declarations, and required
sanitized-summary evidence. Parsing rejects malformed JSON, duplicate/unknown fields, unsupported
versions, missing/null/blank/invalid values, unsafe references/paths, duplicate IDs, prohibited
credential/framing headers, and configured bounds. Values defensively copy collections; failures
use stable sanitized codes with no retained cause or stack trace.

The B-level execution proof only opens and parses prepared source, closes the handle, and returns a
correlated zero-artifact SDK result. It does not register in production, resolve a secret, publish
evidence, contact a target, resolve DNS, enforce runtime SSRF, follow redirects, perform TLS,
materialize authentication, execute assertions/retries, or change platform lifecycle/persistence.
Those responsibilities remain AS-029C through AS-029E as assigned by the implementation plan.

## AS-029C - Outbound HTTP and SSRF-Safe Transport

AS-029C adds sequential unauthenticated request execution behind an immutable constructor-injected
runner policy. The engine validates the admitted HTTP/HTTPS origin, rejects authority ambiguity and
raw path queries, deterministically builds relative paths and parameters, resolves and classifies
every address, denies non-global IPv4/IPv6 destinations by default, and permits non-global access
only for an exact operator-admitted scheme/host/port origin. The authorized address set is pinned
into the connection resolver while the logical hostname remains available for HTTP Host, TLS SNI,
and certificate hostname verification.

The provider disables redirects, cookies, implicit proxies, and automatic content decoding. It
uses bounded connect/socket timeouts plus an absolute abort deadline, closes client/response/source
resources deterministically, bounds source and inline request bytes, and independently bounds
response wire bytes, gzip-decoded bytes, response header count/name/value sizes, and controls.
Unsupported or nested encodings fail closed. Status-only assertions map mismatch to a correlated
SDK `FAILED` result; configuration, policy, timeout, and transport faults remain sanitized errors.
Secrets are never resolved and artifacts are never published.

Security regressions cover raw-query injection; loopback, private, metadata, carrier-grade NAT,
documentation, benchmark, IPv4-mapped, and special IPv6 destinations; exact loopback test-policy
admission; one-resolution address pinning; origin escape; disabled redirects; absolute deadlines;
wire/decompression bounds; response-header boundaries; and correlated status failure. Focused
verification passed 40 tests (15 conformance plus 25 provider), with zero failures, errors, or
skips.

The watched-worktree `mvn clean verify` reproduced the known generated-artifact lock. A snapshot
containing the exact current source was hash-verified across 727 files and excluded generated
outputs. Its six-module `mvn clean verify` passed 1,223 tests with zero failures, zero errors, and 17
skips; local Docker was used only by existing Testcontainers integration tests. Independent
architecture, security, and compatibility reviews initially identified contract metadata, result
mapping, URI, address classification, deadline, header-bound, and regression gaps; all were
resolved, and final classifications are `NONE`.

## AS-029D - Authentication, Assertions, Correlation, and Retries

AS-029D implements only the repository-authorized story scope. Authentication supports NONE, bearer,
basic username/password, and API-key header/query forms using logical references resolved after target
authorization through `ExecutionSecretAccess`. Every `ResolvedSecret` is attempt-local and closes on
success and all failure paths. Credential-managed channels are authoritative and cannot collide with
generic headers, parameters, correlation, framing, cookies, or routing controls.

Response validation supports existing status ranges plus exact case-insensitive headers, bounded simple
JSON paths with scalar equality and existence/nonexistence predicates, and a deliberately narrow local
JSON Schema subset (`type`, `required`, `properties`). Response JSON is byte-, depth-, string-, and
node-bounded. Schemas use bounded prepared-source access only, reject unsafe paths, oversize/deep input,
all `$ref` forms, unsupported keywords, remote retrieval, and raw diagnostic content.

Correlation can inject only the authoritative execution UUID into one validated manifest-selected header;
the manifest cannot supply its value. Provider request retry defaults to zero, permits only transient
transport/timeouts for idempotent methods, reauthorizes DNS/origin and rematerializes credentials per
attempt, applies bounded exponential backoff, and shares one monotonic request deadline. It does not
become AS-022 execution retry and never retries authentication, assertions, schemas, or policy failures.

The watched worktree reproduced the known generated-class interference: `javap` showed an imported SDK
parameter rewritten to an unresolved default-package descriptor. An exact-source snapshot excluded
generated outputs and was SHA-256 verified across 731 files with a snapshot-owned JVM temp directory.
Focused verification passed 47 tests (15 conformance plus 32 provider), with zero failures, errors, or
skips. The six-module full reactor compiled and passed the reusable/provider modules and existing unit
tests through the `studio-api` integration boundary, then failed because Testcontainers could not find a
valid Docker environment. The stopped local Docker service could not be started with available service
